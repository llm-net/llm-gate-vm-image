# LLM Gate VM Image

**English** | [简体中文](README.zh-CN.md)

Guest images, and the recipe that builds them, for the Firecracker nodes of [LLM Gate](https://github.com/llm-net/llm-gate).

LLM Gate can manage an x86-64 Linux host as a Firecracker node (running the `llmgate-vmd` daemon) and create one dedicated microVM per VM workspace on it: development tools, repositories and builds run inside that VM, isolated from other workspaces. Every microVM boots from an image released here, made of two parts:

- **Kernel** `vmlinux`: Linux 6.18 as an uncompressed ELF, booted directly by Firecracker on x86-64;
- **System disk** `rootfs.ext4`: a minimal Ubuntu 24.04 plus a set of general development and media tools.

You normally don't download anything here by hand. An LLM Gate device verifies the signed manifest at `https://llm.net/updates/components/vm-image/stable.json`, then installs the exact assets it lists onto a Firecracker node, checking length and SHA-256 before and after decompression, the kernel's ELF architecture and the version marker inside the root filesystem. Devices never follow the "latest" release, only the manifest.

## What's in the image

Versions below are those of release `2610061825-da9f`. Each release's complete package list (name, version, source package and source version) is its `rootfs.packages.txt` asset, and the exact kernel configuration is `kernel.config`.

### Kernel

| Item | Content |
|---|---|
| Version | Linux 6.18.54, unpatched |
| Configuration | Firecracker v1.17.0 guest configuration `microvm-kernel-ci-x86_64-6.18.config` plus [`kernel/llmgate.config`](kernel/llmgate.config) |
| Form | Everything built in, no modules; `/proc/config.gz` available |
| Devices | virtio-blk (system disk `/dev/vda`, data disk `/dev/vdb`), virtio-net (`eth0`), vsock, KVM PTP clock |
| Containers and networking | cgroup v2, namespaces, overlayfs, bridge / veth / vxlan, nftables and iptables, IPVS, ipset, TUN, FUSE |
| Additions | i8042 keyboard for SendCtrlAltDel, `BLK_DEV_WRITE_MOUNTED` (online resize), xtables matches and IPVS schedulers used by k3s / kube-proxy |
| Not included | Nested KVM, WireGuard, Btrfs, CIFS |

### System disk

Ubuntu 24.04 LTS (noble): `mmdebstrap --variant=minbase` plus the packages in [`rootfs/packages.txt`](rootfs/packages.txt), without Recommends. The archive is pinned to the `snapshot.ubuntu.com` timestamp `20260929T000000Z`, so a rebuild gets the same package versions. 465 packages, about 1.3 GiB of content. Man pages, info and documentation are left out (each package's `copyright` is kept); the rule stays in the image, so packages installed later inside the VM are trimmed the same way.

| Category | Software (version) |
|---|---|
| Base system | systemd / udev 255.4, dbus, kmod, iproute2, iputils-ping, procps, psmisc, tzdata, less, nano, vim-tiny, bash-completion, lsb-release |
| Package management | apt 2.8.3, ubuntu-keyring (apt inside the VM uses the official Ubuntu archive) |
| Login and privileges | openssh-server / openssh-client 9.6p1, sudo 1.9.15p5 |
| Development | git 2.43.0, tmux 3.4, build-essential (gcc / g++ 13.3, make 4.3), python3 3.12.3 + python3-venv, perl 5.38, curl 8.5.0, wget, gnupg, jq 1.7.1, rsync, openssl 3.0.13 |
| Archives and files | xz-utils, zstd, bzip2, zip / unzip, file |
| Media tools | ffmpeg 6.1.1, imagemagick 6.9.12, fontconfig + fonts-noto-cjk (CJK fonts) |
| Containers | docker.io 29.1.3, containerd 2.2.1, runc 1.3.4 — installed but not enabled by default; data root on the data disk at `/home/.docker-data` |
| Time and disks | chrony 4.5, e2fsprogs 1.47.0 |

**Not preinstalled:** development tool CLIs (Claude Code, Codex and others), LLM Gate's `gate` and devd, Node.js, Go, the `pip` command (only the wheel bundled for venv), docker compose / buildx. LLM Gate installs them while setting up a workspace, or the repository's `.llmgate/setup.sh` does.

### Built-in configuration

- **User `dev`** (uid / gid 1000): no password login, passwordless sudo, member of `docker`.
- **sshd**: public keys only, no password or root login. The only host key lives on the data disk in `/home/.llmgate-vm/`, generated by the LLM Gate device; none is kept on the system disk or generated at boot. TCP and Unix socket forwarding allowed, `MaxSessions 64`.
- **`/etc/ssh/ssh_known_hosts`**: host keys of github.com and gitlab.com, checked against the official sources at build time.
- **Two disks**: the system disk can be rebuilt wholesale (apt packages, `/usr/local` and changes under `/etc` are lost); the data disk is mounted at `/home` and holds `$HOME`, Docker data and the VM identity. Both grow online to their actual size at every boot.
- **Network**: configured by the kernel command line `ip=`; networkd, resolved and timesyncd are masked. Hostname and DNS are written per VM at boot.
- **Time**: chrony follows the host's KVM PTP clock, falling back to `ntp.ubuntu.com` when that device is absent.
- **First-boot script**: if the workspace repository has `.llmgate/setup.sh`, it runs once as `dev` in the background on the system disk's first boot (and after a rebuild), logging to `/var/log/llmgate-vm/setup.log`.
- **Shutdown**: `poweroff` notifies the node over vsock; `reboot` makes Firecracker exit and the node starts it again.
- **Version marker**: `/etc/llmgate-vm-release` holds one line `lgvm1{<version>|}lgvm1`.

The boot sequence, data disk layout and the full contract between guest and node are documented in [docs/design.md](docs/design.md) (Chinese).

## Releases

Each release tag is the image version (`YYMMDDHHMM-xxxx`, the same format as LLM Gate firmware, no `v` prefix) and points at the recipe commit that built it. Assets:

| Asset | Content |
|---|---|
| `vmlinux-<version>-x86_64.gz` | Linux kernel, uncompressed ELF, gzip-compressed |
| `rootfs-<version>-x86_64.ext4.gz` | Ubuntu 24.04 root filesystem (ext4 image), gzip-compressed |
| `image.json` | Version, platform, and the length and SHA-256 of both parts before and after decompression |
| `kernel.config` | Complete kernel configuration used for the build |
| `rootfs.packages.txt` | Every package in the root filesystem with its version, source package and source version |
| `SOURCES.txt` | Licenses and source locations |
| `linux-<kernel version>.tar.xz` | Unmodified upstream kernel source |
| `SHA256SUMS` | SHA-256 of the other assets |

Verify a download with `sha256sum -c SHA256SUMS`. In tag `2610061825-da9f` the recipe lives under `firmware/vmimage/`; later versions keep it at the repository root.

## Build

Building needs Linux x86-64, root, about 10 GiB of free space and HTTPS access to `cdn.kernel.org` and `snapshot.ubuntu.com`; the boot test also needs `/dev/kvm`. On Ubuntu 24.04:

```sh
sudo make deps                          # build dependencies
make print-version                      # take the version once and pass it to every later step
sudo make image VERSION=<version>       # output: bin/<version>/
sudo make boot-test VERSION=<version>   # boot smoke test
```

The kernel version and SHA-256, the Firecracker guest configuration and the Ubuntu snapshot timestamp are pinned in `build.sh`, so rebuilding a tag uses the same kernel configuration and the same package versions. Build details are in [docs/design.md](docs/design.md), release and upgrade procedures in [docs/maintenance.md](docs/maintenance.md) (both Chinese).
